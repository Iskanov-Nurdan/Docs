# ALI trade

Совместная работа с таблицами: одновременное редактирование ячеек, формулы,
история версий, права доступа, поиск по содержимому и выгрузка в Excel.

Текстовый редактор убран целиком — и с фронта, и с бэкенда. Документы,
созданные им раньше, удалены миграцией `0005_drop_text_documents`; выгрузка
их содержимого сделана до удаления и лежит в `backups/`.

## Что уже работает

**Ядро** — то, ради чего всё затевалось (разделы 103–107 ТЗ):

- редактор на TipTap/ProseMirror: документ хранится деревом узлов, а не строкой HTML;
- совместное редактирование через Yjs (CRDT): правки двух человек в один абзац
  сливаются, не затирая друг друга;
- WebSocket на Django Channels: приращения, курсоры, присутствие участников;
- работа без сети: правки копятся в IndexedDB и уходят на сервер при восстановлении связи;
- автосохранение — отдельной кнопки нет.

**Учётные записи**: самостоятельной регистрации нет — первого человека заводит
`createsuperuser`, он же главный админ, дальше учётные записи создаёт
администратор на странице `/admin`. Вход, продление сессии, восстановление
и смена пароля, профиль, язык, тема.

**Документы**: создание, папки с деревом и перемещением, избранное, корзина
с восстановлением, раздел «Доступные мне», полнотекстовый поиск PostgreSQL,
копирование, переименование, сортировка, вид сеткой и списком.

**Доступ**: роли владельца, редактора, комментатора и читателя; доступ по ссылке;
запрет скачивания, копирования и печати. Проверка одна на всё приложение —
`AccessService.require`.

**Совместная работа**: панель обсуждения справа от документа — ветки ответов, реакции,
задачи с исполнителем, закрытие и повторное открытие. Комментарий привязывается
к выделенному месту и подсвечивается в тексте.

**Предложения правок**: режим «Советы» — правка не попадает в текст сразу, редактор
или владелец принимает или отклоняет её. Принятая правка применяется к документу
и расходится остальным участникам через CRDT.

**История версий**: снимки по расписанию и по требованию, просмотр старой версии
и восстановление — без удаления предыдущих версий.

**Настройка доступа**: приглашение по почте с выбором роли, изменение и отзыв прав,
доступ по ссылке, запрет скачивания, копирования и печати.

**Параметры страницы**: режимы Pages и Pageless, формат листа, ориентация, поля, цвет.

**Файлы**: загрузка изображений с проверкой настоящего типа, выгрузка книги
в Excel, CSV, PDF, DOCX, HTML и текст с табуляцией — в фоне через Celery.

**Публикация**: документ отдаётся по адресу `/public/document/{public_id}` снимком,
чтобы черновые правки не уходили читателям сразу. Страница открывается без входа
в систему.

**Таблицы**: отдельный вид документа — книга с листами, ячейками и формулами
(`СУММ`, `ЕСЛИ`, `СЧЁТЕСЛИ` и другие), совместная правка через тот же CRDT,
выгрузка в Excel (.xlsx), CSV, PDF, DOCX и текст с табуляцией.

**Цветные статусы**: ячейка красится по смыслу слова — «Просрочка» красным,
«Налог» оранжевым, «В пути» синим, «Готово» зелёным. Слова понимаются на
русском, кыргызском, английском и китайском.

**Просрочка по времени**: колонка со сроком («Прибытие», «Срок», «到达»)
краснеет сама, когда указанное время проходит, и желтеет за два часа до него.
Строка, закрытая словом «Готово» или «Отменён», не краснеет. Пересчёт идёт
раз в минуту, документ для этого править не нужно.

**Готовые таблицы**: журнал рейсов (машина, откуда, куда, время выхода,
статус), заказы и долги — с формулами и статусами. Заводятся миграцией,
поэтому есть сразу после развёртывания.

**Поиск**: по названию и содержимому, включая ячейки таблиц. Ищет и по целым
словам с учётом морфологии, и по фрагменту — «450» находит счёт «СЧ-4501-А»
(триграммный индекс). В выдаче показывается кусок текста вокруг найденного
с подсветкой. Внутри таблицы — свой поиск по Ctrl+F с переходом по совпадениям.

**Права в системе**: пользователь, администратор и главный админ. Страница
`/admin` — сводка, поиск людей, заведение учётных записей, закрытие и возврат
доступа. Назначать администраторов и заводить их может только главный админ.
Себя заблокировать нельзя, главного админа — тоже.

**Интерфейс**: боковая панель с разделами и папками, колокольчик уведомлений,
галерея шаблонов, настройки профиля с темой и сменой пароля, восстановление
пароля и подтверждение почты по ссылке из письма, меню «Файл» в редакторе —
выгрузка в PDF, DOCX, TXT, HTML и печать, импорт DOCX, TXT и HTML из списка
документов.

### Таблицы из файлов и заготовки

- **Открыть файл Excel или CSV** — кнопка со стрелкой в шапке. Переносятся все
  листы, формулы и даты; формула с функцией, которой редактор не знает,
  заменяется посчитанным Excel значением, а если его нет — переносится как есть.
- **Сохранить как шаблон** — в меню «Файл» редактора. Своя заготовка видна
  только автору и лежит в галерее рядом с общими.

### Работа со столбцом

Значок ⌄ у буквы столбца открывает его меню:

- **сортировка** по возрастанию и убыванию. Переставляются строки целиком,
  формулы внутри переезжают вместе с ними («=E2*F2» в пятой строке становится
  «=E5*F5»). Шапка и итоговая строка с формулами остаются на местах;
- **фильтр** — галочки по значениям столбца. Скрытые строки схлопываются,
  итог под таблицей фильтр не прячет: как раз при отборе на него и смотрят;
- **список значений** — в ячейках столбца появляется выбор вместо набора
  руками. Готовый список можно собрать из того, что в столбце уже есть;
- **правило подсветки** — свой цвет по условию («больше 100000», «содержит
  просрочку»). Правило сильнее автоматической подсказки по смыслу слова, но
  слабее заливки, выбранной вручную;
- **закрепление столбцов** до выбранного.

Шапка закрепляется кнопкой в панели: строка остаётся на месте при прокрутке.

**Диаграммы** — кнопка со столбиками в панели. Строятся по двум столбцам:
подписи и числа; вид — столбики, линия или круг. Диаграмма хранится в листе и
читает те же ячейки, поэтому после правки данных показывает новое сама.

## Чего ещё нет

Список ТЗ писался под текстовый редактор. Половина его пунктов — колонтитулы,
сноски, оглавление, закладки, smart chips, линейка, вставляемые готовые блоки —
относится к документу со страницами, а такого документа в приложении больше нет:
он заменён таблицей (миграции `0005_drop_text_documents`, `0006_sheets_only`).
Переносить их в таблицу не во что.

Из того, что к таблице применимо, закрыто всё: сортировка и фильтры,
закрепление шапки и столбцов, списки значений в ячейках, свои правила
подсветки и диаграммы — см. раздел «Работа со столбцом» выше.

Осталось за рамками: совместное редактирование одной ячейки посимвольно
(сейчас правка ячейки — целиком, последний сохранивший выигрывает), сводные
таблицы и макросы.

## Запуск

Нужен Docker с плагином Compose.

```bash
cp .env.example .env
# задайте POSTGRES_PASSWORD и DJANGO_SECRET_KEY
docker compose up -d --build
```

Через минуту-две:

- приложение — http://localhost:8080
- API — http://localhost:8080/api/
- админка — http://localhost:8080/django-admin/

Первый администратор:

```bash
docker compose exec api python manage.py createsuperuser
```

## Запуск на сервере

Разворачивается одной командой. Нужен сервер с Docker, открытыми портами 80
и 443, и домен, A-запись которого уже указывает на его адрес.

```bash
git clone <адрес репозитория> docs && cd docs
cp .env.prod.example .env
nano .env                 # домен, пароли, почта
./scripts/deploy.sh
```

Скрипт по порядку: проверяет настройки, собирает образы, поднимает службы,
выпускает сертификат Let's Encrypt и переводит nginx на https. Повторный
запуск обновляет работающую установку — сертификат при этом не трогается,
его продлевает служба `certbot` сама.

Что заполнить в `.env` обязательно:

| Переменная | Чем заполнить |
|---|---|
| `DOMAIN` | Имя, по которому открывается приложение |
| `LETSENCRYPT_EMAIL` | Живой адрес: на него придёт письмо, если сертификат перестанет продлеваться |
| `DJANGO_SECRET_KEY` | `openssl rand -base64 48`. Смена ключа выбрасывает всех из системы |
| `POSTGRES_PASSWORD` | `openssl rand -base64 24` |
| `DJANGO_ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS`, `CORS_ALLOWED_ORIGINS` | Тот же домен |
| `EMAIL_*` | Настоящий SMTP. Без него не работают подтверждение адреса и сброс пароля |

Первый администратор заводится после развёртывания:

```bash
docker compose -f docker-compose.prod.yml exec api python manage.py createsuperuser
```

Дальше учётные записи заводятся в самом приложении, в разделе «Админ»:
открытой регистрации нет намеренно.

### Обслуживание

```bash
C="docker compose -f docker-compose.prod.yml"

$C ps                     # что запущено
$C logs -f api            # журнал приложения
$C logs -f worker         # выгрузки, письма, уборка корзины
$C restart api            # перезапуск после правки .env
./scripts/deploy.sh       # обновление после git pull
```

Резервная копия базы и файлов:

```bash
$C exec -T db pg_dump -U docs docs | gzip > backup-$(date +%F).sql.gz
docker run --rm -v docs-prod_media_files:/data -v $(pwd):/out alpine   tar czf /out/media-$(date +%F).tar.gz -C /data .
```

Восстановление базы из копии:

```bash
gunzip -c backup-2026-09-12.sql.gz | $C exec -T db psql -U docs docs
```

### Чем боевой контур отличается от локального

- код лежит внутри образа, а не монтируется с хоста: обновление идёт только
  пересборкой, правкой файла на сервере контейнер не изменить;
- наружу открыты только 80 и 443. База, Redis и приложение доступны лишь
  внутри сети docker;
- фронтенд собран заранее и раздаётся статикой, сервера разработки нет;
- на вход и сброс пароля стоит ограничение частоты запросов — один в секунду
  с адреса; на остальной API — двадцать;
- сертификат продлевается сам, nginx перечитывает его каждые шесть часов.

### Метки в тексте

Подсветка комментариев и предложенных правок — это декорации ProseMirror,
а не разметка внутри документа. Иначе метка комментатора уходила бы всем
приращением Yjs, то есть правкой текста, на которую у него нет права.

Позиция метки хранится вместе с цитатой: текст правят и после комментария,
поэтому при расхождении место ищется по цитате (`editor/locate.ts`).

### Как хранится документ

Содержимое живёт в двух видах:

- **`ydoc_state`** — двоичное состояние Yjs. Оно главное при совместной работе:
  только CRDT сливает правки двух людей в один участок текста без потерь.
- **`content`** — то же дерево узлов ProseMirror в JSON. Нужно всему, что работает
  без редактора: поиск, экспорт, печать, версии, публикация.

Сервер не разбирает приращения Yjs — он складывает их в журнал и раздаёт остальным.
Свёрнутое состояние присылает та вкладка, где документ открыт; после этого журнал
очищается. Так сервер обходится без реализации CRDT на Python, ничего не теряя.

Хранить один HTML и перезаписывать его целиком нельзя: при одновременной правке
победил бы тот, кто сохранил последним.
