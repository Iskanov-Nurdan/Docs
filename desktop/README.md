# ALI trade для Windows и macOS

Отдельное приложение с ярлыком на рабочем столе. Внутри — тот же сайт
`https://app.alitrade.tw1.ru`, только в своём окне, без вкладок и адресной
строки браузера. Сотрудники скачивают его со страницы `/download` на сайте.

Интерфейс в приложение не зашит: всё, что выкладывается на сервер
(`scripts/push-web.sh`), появляется в приложении при следующем запуске само.
Пересобирать и переустанавливать приложение нужно, только если менялся код
в этой папке.

## Что умеет

- запоминает размер и положение окна;
- второй запуск не открывает второе окно, а поднимает уже открытое;
- без интернета показывает «Нет связи с сервером» и сам повторяет каждые
  15 секунд; правки, сделанные до обрыва, лежат в профиле приложения и уходят
  на сервер, когда связь вернётся;
- чужие ссылки открываются в обычном браузере, страница не получает доступа
  к файлам и системе;
- вход сохраняется между запусками;
- меню скрыто, `Alt` показывает его: обновить (`F5`), без кеша (`Ctrl+F5`),
  масштаб (`Ctrl` `+`/`-`/`0`), во весь экран (`F11`).

## Выпуск новой версии

1. Поднять `version` в `package.json` (например, `1.0.1`).
2. Собрать установщики:
   - **Windows** — у себя: `cd desktop && npm install && npm run dist`;
   - **macOS** — `.dmg` собирается только на Mac. Без Mac: GitHub → Actions →
     «Приложение для компьютера» → Run workflow (или тег
     `git tag desktop-v1.0.1 && git push --tags`). Оба установщика лежат
     в артефактах запуска — скачайте их в `desktop/dist/`.
3. Выложить на сайт:
   ```bash
   SERVER=root@81.200.144.71 ./scripts/push-desktop.sh
   ```
   Скрипт берёт из `desktop/dist/` файлы текущей версии
   (`ALI-trade-Setup-<версия>.exe`, `ALI-trade-<версия>-mac.dmg`), заливает
   их в `/opt/alitrade/downloads/` и пишет `latest.json` — по нему страница
   «Скачать» показывает версию и размеры. Достаточно и одного установщика:
   для второй системы страница напишет «готовится».

Без `SERVER` скрипт только раскладывает файлы в `downloads/` — так страницу
можно проверить на локальном docker: http://localhost:8080/download.

Первый раз после появления страницы на сервере нужно один раз запустить
`./scripts/deploy.sh`: nginx должен узнать про `/downloads/`.

## Запуск без установки

```bash
npm start        # рабочий сервер
npm run dev      # локальный docker: http://localhost:8080
```

Любой другой адрес — через переменную `ALITRADE_URL`.

> Если `npm start` из терминала VS Code открывает не окно, а ошибку
> «Cannot find module 'electron'», в терминале стоит `ELECTRON_RUN_AS_NODE=1`
> (её выставляет сам VS Code). Запускайте из обычного терминала или сбросьте
> переменную: PowerShell — `Remove-Item Env:ELECTRON_RUN_AS_NODE`.

## Предупреждения при первом запуске

Установщики не подписаны платным сертификатом разработчика, поэтому система
предупреждает при первом запуске:

- **Windows** — «Windows защитила ваш компьютер»: «Подробнее» → «Выполнить
  в любом случае»;
- **macOS** — «Не удаётся проверить разработчика»: правой кнопкой по
  приложению → «Открыть» → «Открыть». На новых macOS — «Системные настройки» →
  «Конфиденциальность и безопасность» → «Всё равно открыть».

Приложение для Mac подписано ad-hoc (без сертификата) — этого достаточно,
чтобы оно запускалось на Apple M1–M4. Чтобы предупреждений не было совсем,
нужны сертификаты: Apple Developer ($99 в год) и сертификат подписи кода
для Windows.
